# Planner workspace contract

## Browser skeleton

| Route | Screen and observable behavior |
| --- | --- |
| `/sign-in`, `/recover`, `/enroll-mfa` | Sign in by email or username, consume a one-time operator grant, and finish required MFA before ordinary access. Keep the requested authorized destination through sign-in. |
| `/workspace` | Project sidebar with authorized project search and favorites. Switch grouped or grid presentation, sort by default, name or creation, and allow eligible users to reveal hidden projects explicitly. |
| `/projects/:projectId` | Project overview, editable name and description, board order, background selection, manager settings and base custom-field templates. |
| `/boards/:boardId?context=board\|archive\|trash&view=kanban\|grid\|list` | Shared query and selection engine for BoardCanvas, BoardGrid and BoardTable. Command bar for search, filters, saved recipes, settings and a keyboard move action. Archive and trash default to list and use grid or list. Normal board defaults to the board preference. |
| `/boards/:boardId/cards/:cardId` | Deep-linkable inspector with description, fields, labels, members, due date, stopwatch, checklists, files, comments and activity. Browser back restores board selection and focus. Direct access uses the same ACL as board reads. |
| `/inbox`, `/settings/profile`, `/settings/preferences`, `/settings/security`, `/admin/accounts` | Read states and grouping, profile and avatar, user preferences, MFA and connections, and administrator account operations. These screens use the same permission flags and mutations as their backend operations. |

Use the design's original sidebar, command bar and inspector to distinguish Planner's layout and visual treatment. Support loading, empty, read-only, missing resource and recoverable error states. The three board views retain the same filtered item identity and permitted commands. Maintain per-tab view memory by generation, user, board and context, with an explicit URL view winning. Save named filter recipes and the last cleared recipe to the browser on that same scope. Restore them only on user action. Sign-out clears session state. Test cross-account, two tabs, and deep links with a changed ACL. Keyboard users can move cards and lists by choosing a destination and anchor in a dialog. It sends the same mutation as pointer drag, restores focus, and announces the result. Narrow layout uses a full-width inspector with the same actions.

## Transport conventions

Start REST at `/api/v1`. Read responses use `{data}` and paginated responses add `page: {nextCursor}`. Commands use JSON, return the affected authoritative DTOs and revisions, and require `Idempotency-Key`. On mutations of existing resources use a quoted integer `If-Match` for the target revision. Use the same values as `idempotencyKey` and `expectedRevision` in MCP arguments. Map missing authentication to `401`, inaccessible and unknown resources to `404`, insufficient capabilities on visible resources to `403`, stale revisions or vanished anchors to `409`, and invalid shapes or impossible transitions to `422`. Errors use `{error:{code,message,requestId,fields?}}`. Schema fields define allowed projection, size, and enum. Refuse unknown command properties.

The workspace bootstrap reads board, project summary, content permission flags, list and label DTOs, board preferences, order versions and latest event sequence. Fetch card pages through one query. Board, card, event, file and search responses use the same actor established by the backend. Create responses return `201`. Ordinary reads and edits return `200`. Delete returns `204` or a transition result when the resource moves to trash.

Entity DTOs use `id`, `revision`, `createdAt` and `updatedAt`, plus typed parent IDs and fields in the relevant operation row. Use `name` for the displayed title. Normalize surrounding whitespace on named entities and bound new project, board, list, card and task names to 128 characters. Preserve imported longer names and raw descriptions. Restrict command schemas to writable fields. Omitted patch fields stay unchanged and explicit null clears nullable values. Expose `permissions` on project, board and card reads. Group and child mutations return the affected parent's new revision. Validate enums in shared schemas and UTC instant types at the boundary.

Project detail returns visible board summaries. A manager also receives the manager roster, usable background references and project field templates. Card detail returns its list and board identity, label and assignee projections, attachments, cover, field groups and values. Fetch checklist contents, comments and activity by their scoped reads. Archive/trash show detail with restore, move and authorized disposal actions. Normal editor controls become available after restoration.

## Workspace and card operations

Prefixes below are relative to `/api/v1`. Compound requests and edits use the field rules in the rows that follow.

| API family | Contract and operation IDs |
| --- | --- |
| `GET/POST /projects`, `GET/PATCH/DELETE /projects/:id` | `projects.list/create/get/update/delete`. List returns accessible summaries and authorized hidden/favorite state. New project has name, optional description, explicit private/shared type per role and a manager default. Edits include name, description, independent hidden state, background and ownership changes through scoped checks. Delete confirms a named project and atomically removes its active projection. |
| `PUT/DELETE /projects/:id/favorite`, `POST /projects/:id/managers`, `DELETE /projects/:id/managers/:userId`, `POST /projects/:id/backgrounds`, `DELETE /projects/:id/backgrounds/:backgroundId` | `projects.favorite/unfavorite/addManager/removeManager/uploadBackground/removeBackground`. Favorite is per actor. Manager identity is an existing eligible account. Background supports preset gradient or an uploaded image belonging to that project. Prevent cross-project reuse by ID. |
| `GET/POST /projects/:id/boards`, `GET/PATCH/DELETE /boards/:id`, `POST /boards/:id/move` | `boards.list/create/get/update/delete/move`. Manager creates a board with system lists and appends it to the project. Support within-project board ordering by neighbor. Board settings persist name, default view, card type default/restriction, creator visibility, card age, counter and expanded checklists. |
| `GET /boards/:id/workspace`, `GET /boards/:id/cards`, `GET /boards/:id/events` | `boards.workspace/cards/events`. Card query fields are `context,q,labelsAny,labelsNone,members,listIds,unassigned,limit,cursor`. Apply authorization before filters, counts and pagination. SSE uses the platform event contract. |
| `GET/POST /boards/:id/members`, `PATCH/DELETE /boards/:id/members/:userId`, `PUT/DELETE /boards/:id/follow` | `boards.members/addMember/updateMember/removeMember/follow/unfollow`. Board editors and viewers are explicit membership roles. Viewer comment permission is a Boolean. Editors require a null comment override. Follow requires direct membership. |
| `GET /projects/:id/manager-candidates`, `GET /boards/:id/member-candidates` | `projects.managerCandidates` and `boards.memberCandidates`. List active eligible results not yet assigned, filtered by name or username and paginated. Return only ID, name and nullable username. Enforce the caller's add rule and return at most self for self-only board managers. |
| `POST /boards/:id/lists`, `PATCH/DELETE /lists/:id`, `POST /lists/:id/{move,sort,archive-cards}`, `POST /boards/:id/trash/clear` | `lists.create/update/delete/move/sort/archiveCards/clearTrash`. Create finite active/closed lists, update name/color, reorder or transfer eligible finite lists, sort finite card contents, bulk archive closed-list cards, and explicitly clear trash. Use destination board, neighboring list ID and versions when transferring. |
| `POST /lists/:id/cards`, `GET/PATCH /cards/:id`, `POST /cards/:id/{move,duplicate,archive,restore,trash,purge}` | `cards.create/get/update/move/duplicate/archive/restore/trash/purge`. Creation takes `name,type?,description?,beforeCardId?`. Updates cover name, description, allowed type, due date and completion, cover association, stopwatch state and closed state. Transitions name an eligible list where needed. Purge requires explicit confirmation. |
| `GET/POST /boards/:id/labels`, `PATCH/DELETE /labels/:id`, `PUT/DELETE /cards/:id/{labels,assignees}/:relatedId` | `labels.list/create/update/delete` and `cards.addLabel/removeLabel/assign/unassign`. Labels are board-owned and can have no name. Assignees must be destination board members. Link writes are idempotent and preserve creation metadata on existing links. |
| `GET/POST /cards/:id/checklists`, `PATCH/DELETE /checklists/:id`, `POST /checklists/:id/tasks`, `PATCH/DELETE /tasks/:id`, `POST /tasks/:id/move` | `checklists.list/create/update/delete` and `tasks.create/update/delete/move`. Checklist has name, rank, front-of-card and hide-completed settings. Task has name or linked target, nullable assignee and completion. Move supplies destination checklist and neighbor. |
| `POST /projects/:id/field-templates`, `POST /{boards,cards}/:id/field-groups`, `PATCH/DELETE /field-groups/:id`, `POST /field-groups/:id/fields`, `PATCH/DELETE /fields/:id`, `PUT/DELETE /cards/:id/field-values/:groupId/:fieldId` | `fields.createTemplate/createGroup/updateGroup/deleteGroup/create/update/delete/setValue/clearValue`. Use a shared group ID address for template edits and definitions. Group may instantiate a project base template. Values are exact text, maximum 512 characters. Field front-of-card flag is independent of its value. |
| `GET/POST /cards/:id/comments`, `PATCH/DELETE /comments/:id`, `GET /{boards,cards}/:id/activity`, `PUT/DELETE /cards/:id/follow` | `comments.list/create/update/delete`, `activity.board/card`, and `cards.follow/unfollow`. Comment creation, editing and moderation use separate permission checks. Activity and in-app fanout have the rules in the access contract. |
| `POST /cards/:id/attachment-links`, `POST /cards/:id/attachment-files`, `PATCH/DELETE /attachments/:id`, `GET/HEAD /attachments/:id/download`, `GET/HEAD /attachments/:id/thumbnail/:variant` | `attachments.addLink/addFile/update/delete/download/thumbnail`. Links allow HTTP(S) and stay inert in the backend. Upload multipart file once under the ID and size policies. Display name is separate from the storage key. Changing the name keeps the same blob. |
| `GET /notifications`, `PATCH /notifications/:id`, `POST /notifications/read-all`, `POST /cards/:id/notifications/read` | `notifications.list/update/readAll/readCard`. Scope by recipient and current target access. Return filtered count and cursor and persist read state. |

### Placement and destructive actions

1. A board contains one archive and one trash system list created in the board-create command. Their ranks are null. A finite list is active or closed, has a stable rank and accepts direct edits and finite ordering. System names and placement are fixed. Ordinary board views exclude archive and trash. Archive and trash use `listChangedAt DESC,historySequence DESC,id DESC` and cursor pagination. The importer assigns the historical sequence to preserve source bigint ID ordering when timestamps tie. Allocate a higher sequence on each new arrival.
2. Move uses `{toListId,beforeCardId:null|string,sourceOrderVersion,destinationOrderVersion}`. Null anchor appends. Validate source and destination access and versions, remove the moving card from the order before resolving the anchor, and reject self or foreign anchors. Allocate ranks in the backend. Touch affected list order versions and changed card revision in the same command. A concurrent stale move returns the current revisions and causes the browser to reload.
3. Entering a finite closed list closes the card and updates linked task completion. Entering a finite active list reopens it. Archive and trash preserve existing completion and store a surviving previous finite list when applicable. Explicit restore requires an eligible target on the same board or reuses a surviving previous eligible list. A missing prior list yields `422 RESTORE_TARGET_REQUIRED` and the picker, preserving historical provenance. A list delete moves its occupants to trash and removes the list from finite ordering.
4. Sort finite lists by title, due date or creation date with an explicit direction, deterministic case folding, stable ID tie-break and missing due dates last. The bulk archive operation covers a closed finite list into the same board's archive. An arbitrary bulk move is outside this operation. Clear affects only the confirmed trash list, requires its current version and unlinks affected dependents through the command journal. Exclude permanent trash purge from MCP.
5. Cross-board card and finite-list moves validate source and destination access and re-evaluate every card edge. Keep destination-eligible assignees and follows, remove others, clear ineligible task assignees, match destination labels by normalized name or create a label with the same presentation under destination permission, and preserve field text by detaching incompatible templates into owned definitions. Report remaps in the action summary. Preserve comment and activity history under the resulting card's access rules. Move finite lists as one journaled command with the same rules per occupant. Apply board card-type restrictions to new cards and explicit type edits. Preserve the existing type during moves or import. Project and board deletion require typed confirmation, with a retained operator backup as the recovery path.
6. Duplicate issues a new card ID, new checklist/task/attachment IDs and an independent file reference per cloned attachment. Copy card content, eligible members and labels, checklist state and custom-field values. Rebind the cover to the cloned attachment. Use the same cross-board eligibility and field remaps as move. Start independent timestamps and activity. Leave original comments, follows and history with the source card. A purged linked card replaces external links with an unavailable-task projection. Preserve target name, completion and ID only in restricted historical provenance. The projection has no link or derived completion for ordinary callers.
7. Deleting a populated board is a single journaled command. Remove its active card/list/label, membership, content and notification projections, retain protected audit provenance, replace externally linked tasks with the same unavailable projection and release only the deleted attachment references. Keep shared blobs available through surviving authorized references. Audit the responsible manager, re-evaluate project board counts and send scoped removal events while evicting open sessions from the deleted board. Project deletion requires no remaining boards.

### Content, filters and files

- Editable descriptions use Markdown as storage with rich editing and plain text Markdown modes. Preserve imported text even where Planner renders unsafe HTML as text or omits it from rendered content. Guard mention lookup by board eligibility, present display name when username is null, and escape all user content. Test Unicode and malformed links. Store a per-generation, user and card local draft with base revision, editor mode and last modified time for up to seven days. On reopening with a different revision, offer original draft and latest content with a choice to discard or copy. Explicit save or discard clears the draft.
- Board cut and copy accumulate a single selected card and source revision in tab memory. Paste opens a destination-list/anchor chooser, uses `cards.move` or `cards.duplicate`, and keeps all normal source and destination checks. Clear a successful cut and keep copy available for another explicit paste. Clear clipboard on sign-out or access loss.
- Checklist linked tasks have a readable target and may be reordered or moved between groups on their owning card. Check editor access to the source and read access to the linked target. Update linked completion on target close or reopen. A user who can read only the source sees a neutral unavailable link without the target ID or title. Field values use the exact card/group/definition tuple. Verify the group is in card or board scope and that the definition belongs to that instance or its template.
- Query normalizes case, splits on whitespace, commas and semicolons, ANDs literal terms across title and description, and applies selected filter groups together. Positive label filters match any chosen label, negative labels exclude a card, member selection matches card assignees or checklist assignees, and unassigned means no card assignee. Use bounded RE2-compatible matching for slash-delimited patterns. Invalid active patterns return zero results and a validation indicator. Apply bounded queries on the authorized board only. Preserve stable ordering and bind cursors to filters.
- Use a private file reference for each attachment, avatar or background. Create an image cover for the first eligible image if no cover exists. Updating a cover accepts only a current image attachment on the same card. Removing the cover clears the pointer. Permit download and range validation only after resolving current card and board access. Report a metadata-only imported file as unavailable with no working download route until a verified matching asset is attached.
- Support JPEG, PNG, GIF, WebP and safe passive attachment types. Untrusted files default to download with no inline HTML or SVG execution. Enforce 32 MiB for normal uploads and verify the reported length. Import may preserve larger verified source files if disk preflight passes. Stage bytes and image variants before reference commit. Link files by the generated reference and digest. Head/range/thumbnail checks share the same authorization as full download.

## Verification fixtures

- Run the same stable seed through browser and REST tests. Include private and shared projects, hidden workspace state, at least two active editors, viewer with and without comments, null username, denied linked target, a closed list and mixed active/archive/trash cards.
- Check move into a closed list, restore after original list removal, atomic bulk archive, failed clear on stale version, duplicate then delete one attachment ref, cross-board label and field remapping, forbidden destination, and overlaid two-tab edits. Compare database order, browser cards, permissions, activity and audit as appropriate.
- Verify per-tab state, keyboard announcements and focus, with 1440×900 desktop and 390×844 mobile viewports. Run one case each from Kanban, Grid and List and check direct card links and permission loss with an open inspector.
- Check archive and trash pagination, ties in source rank, zero visible cards for invalid regex, positive and negative filters, isolated preferences and stale board event replay under access revocation.

The restored reference has 250 cards across three boards, with active, archive and trash examples. Its absent closed lists, story cards, linked tasks, custom field values and viewer memberships need synthetic cases. The source also offers Trello JSON board creation. Planner 0.1.0 uses the PLANKA install-time migration and leaves Trello import for a separate decision.
